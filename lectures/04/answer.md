## 宿題

- 取り組んだレベル：基礎
- やったこと：採点のモデル（AIE_MODEL）だけを gemini-3.1-flash-lite から gemini-3.5-flash に変え、演習の STEP 3 で直した後の rubric.md と同じ labels.jsonl に対して再実行した（`AIE_MODEL=gemini-3.5-flash uv run python -m app.judge --wait 15 --out lectures/04/judge_result_hw.json`）。--wait 2 ではレート制限に達したため、15 秒おきにした
- 結果：
  - 変える前（3.1-flash-lite）：根拠 8/10、範囲 10/10、ヒント 10/10、分かりやすさ 9/10、回の表示 10/10、総合 10/10（coverage 100%）、要確認 0 件、不一致 3 件（#04 分かりやすさ、#06 根拠、#08 根拠）
  - 変えた後（3.5-flash）：根拠 8/9、範囲 10/10、ヒント 10/10、分かりやすさ 10/10、回の表示 10/10、総合 9/9（coverage 90%）、要確認 1 件（#05 根拠）、不一致 1 件（#08 根拠）
- 気づき・疑問：
  - 大きいモデルにすると、#06 の根拠（ヒントの失敗を根拠に持ち込む混同）と #04 の分かりやすさの見逃しが直り、不一致は 3 件から 1 件に減った
  - 一方で #05 は、rubric.md に「pass」の方針を書き足したのに再び unsure になった。理由を見ると、参照の「期待するふるまい」にある「一般的な説明をするかどうかは、採点の基準ではまだ決めていない」を根拠にしていた。3.5-flash は参照の文言をより忠実に読むため、rubric.md と評価セットの参照が食い違っていると、その食い違いが表に出る。基準を直したら、評価セットの参照も合わせて直す必要がある
  - #08 の不一致は、3.1-flash-lite では「用語集を全文出した」という範囲の失敗を持ち込んだもので、3.5-flash では「参照に用語集のエントリが無いのに、用語集にないと伝えずに出力した」という理由に変わった。#08 の参照には用語集のエントリが付いていないため、採点器は出力内容が用語集と一致するかを確かめられない。参照の情報が足りないと、モデルを替えても判定はずれる
  - 一致率が高くても、どのモデルが「正しい理由で」一致しているかは、理由を読まないと分からない。また大きいモデルはレート制限が厳しく、採点のコスト（時間・回数）とのトレードオフがある
